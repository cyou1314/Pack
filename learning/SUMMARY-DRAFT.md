# 学习轮总汇（草稿）——开电脑开工前先看这一页

> 材料：六仓拆解（Letta / AutoGen / ChatDev / CrewAI / AstrBot / LangGraph）+ Rakazo 三份 + 合成笔记 SYNTHESIS.md；落地状态以 SPEC v0.9 附录 G 标注为准；开工顺序以 MAC-BATCH.md 为准。

## 1. 一句话总判

七家没有一家和 Pack 同路：任务状态机、调度员唯一关单、多主人批准、零花费登录成员，都是被「跨机器、会掉线、真账号」的执行体形态逼出来的独走；而七家共同验证过的纪律（记忆硬顶、批准规则、出口管制、防重跑、失败分类）已全部落进中枢——Pack 现在缺的不是设计，是执行体接入和 App 呈现。

## 2. 学到的最有价值的 5 件事

1. **任务状态机七家皆无，Pack 独走且站得住**
   结论：主流分活只有静态绑定、进程内直调、LLM 选人、直指派单四种，没有一家做原子认领＋租约心跳＋尝试上限＋独立关单。
   出处：六仓各自拆解的任务层核查（grep claim/lease 全零命中）+ Rakazo Ticket Board 对照（SYNTHESIS §1.1）。
   对 Pack 的意义：这一层不向任何一家靠拢，靠自己的验收守，是 Pack 的真差异点。

2. **记忆的正解是「分层＋硬顶整笔拒绝＋全量留版」**
   结论：常驻小抄、按需档案、全量流水三段式是共识；硬顶只有 Letta 与 Rakazo 真做了，且同构——超限整笔拒绝不截断、限额不许 agent 自改、每次修改全量留版。
   出处：LETTA-TEARDOWN、RAKAZO-TEARDOWN §2（SYNTHESIS §1.2）。
   对 Pack 的意义：记忆系统已照此落地（见 §3 第 5 件），私人记忆红线被两家的 scope 隔离双重验证。

3. **交活要传引用，不要拼文本**
   结论：七家里只有 ChatDev 把交活当一等公民——成果物落共享区、交接只传指针、平台用哈希快照自动生成交活清单；其余各家全是把上游输出全文拼进下游提示词，链越长越膨胀且无校验。
   出处：CHATDEV-TEARDOWN §3、CREWAI-TEARDOWN §2（SYNTHESIS §1.4）。
   对 Pack 的意义：交活信封已落地中枢侧，交活从一段自由文本升级为机器可校验的结构（见 §3 第 6 件）。

4. **批准只有 Rakazo 做成了体系；「回成员自己的主人批准」是 Pack 独有红线**
   结论：三档模式＋预授权规则＋独立审查＋支出限额只有 Rakazo 一家产品化；其余各家只有布尔卡点或只读复核。而多主人拓扑下「不可逆动作回该成员自己的主人批准」七家皆无——因为没有一家是多主人系统。
   出处：RAKAZO-FULL-TEARDOWN §1.1（SYNTHESIS §1.3）。
   对 Pack 的意义：规则库、审查者、出口管制三件已抄到手并上线；多主人批准红线独走且必须坚持。

5. **失败先分类，再决定重试**
   结论：LangGraph 与 ChatDev 两家独立同构——先按失败类型分类（网络/额度类退避重试、逻辑错误类立即停），而不是一律原样重试。
   出处：LANGGRAPH-TEARDOWN §4、CHATDEV-TEARDOWN §6（SYNTHESIS §2 清单第 3 项）。
   对 Pack 的意义：失败分类＋指数退避回池已落地（见 §3 第 6 件），回池不再是无差别重来。

## 5. 明确不学的（每家一句）

- **Letta**：MemFS 全套形式仪式（git 仓库＋frontmatter＋反思子代理）是重机械，只抄它的拒绝式校验纪律，不抄形式。
- **AutoGen**：Swarm 成员自选下家互相派活——正撞调度员唯一仲裁的地基，再优雅也是反面教材。
- **ChatDev**：边条件 fail-open（求值异常当条件成立）——交接宁可停摆也不能错放行。
- **CrewAI**：manager 进程内直调委派（无卡、无状态、无记录）——学它等于拆 Pack 任务卡＋审计的地基。
- **AstrBot**：插件同进程全权限的平信任模型——与最小权限＋全量审计系统性冲突，只借它的入口适配层。
- **LangGraph**：Pregel 运行时底盘本身——为进程内毫秒级节点设计，与 Pack 跨机器分钟级租约双错位，只借思想不换底盘。
- **Rakazo**：API key 接入、默认深色 UI、无状态机直指派、共享云电脑默认形态——附录 G.3 已定案不采纳。

## 6. 风险与存疑

- **全是静态审计**：七家均未真跑——六仓只读代码、Rakazo 的 Docker 全栈未部署验过；运行时行为（真实网络调用、动态加载）不在结论覆盖内。
- **版本钉点**：Rakazo 钉在提交 a77bfbb，六仓钉点见各自 TEARDOWN；七家迭代都快（Rakazo 仍是 beta），结论只对钉点版本负责，引用前先核是否过期。
- **三处「部分落地」要记牢**：出口管制的执行体接入、「已污染」写记忆先问的闸门、运行时层出站拦截均未做——中枢判定已上线不等于防线闭合，闭合在 Mac 批次第 2 项。
- **审查纪律是流程约束**：review_file 只保证字段受限与留痕，「审查时不看页面内容」靠调度员自律，没有代码强制。
- **规则库的自动决议显示为调度员名义**：靠正文后缀与审计 actor 区分真人，App 侧未做视觉区分。
