# v1.1 房间闲聊：施工中止记录

基线 `5fc70ff4153b73824f11af575be5139684bcc4fd`。本片只改 `runtime/` 与本结果文件；尚未部署，群主实测待进行。

## 已施工与测试

- 新增聊天触发分类、连续会话驾驶与运行时水位：owner 不含成员提及的普通消息及 dispatcher 的 `@absent` 召唤进入闲聊；其他作者、系统消息和已读水位跳过。成员提及依 watcher 的大小写、前缀、歧义和边界规则判断；原 watcher 与任务认领代码未改。
- `pack-main` 的网页对话 URL 和水位持久化；首次以种子建立会话，后续复用；任务和闲聊共用浏览器串行占用。每次处理前读成员周额度，达到 90% 或额度不可读则跳过闲聊；连续失败退避，识别到登录页面则停止闲聊。回复限 200 字，不经任务信封。
- `node --check` 三个运行时文件通过；`node --test runtime/tests/*.test.mjs` 六项通过；独立模拟环境的任务 claim、transfer、outgoing、egress、holder loss 五种回归通过。首次检查命令因 shell PATH 未含 node 未启动测试，显式指定本机 Node 后通过。

## 停止点与未实证项

- 部署前只读确认 absent 有无正在执行任务时，直连配置中枢失败（ConnectError）；按当前运行时日志的发现地址并使用服务代理再试，失败（RemoteProtocolError）。同层连续失败两次，按纪律停下；未复制文件到 `~/pack-runtime/`、未重启 launchd，未确认当前任务状态、心跳或实际额度。
- 新聊天驾驶尚未在真实网页上验证；待中枢连接恢复并重新确认无正在执行的任务后部署，核对心跳，再请群主本人发一条普通消息实测。不得冒充 owner 验收。dispatcher 在场钩子由调度员另在 VM 侧实施。
- 生产 App、引擎、桥及 VM 未操作。
