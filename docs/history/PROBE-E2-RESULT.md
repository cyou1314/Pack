## 引擎侧只读复核

账号状态来自本机助手只读状态查询，API 分组来自 `127.0.0.1:47821/v1/status`；vm_state 是 absent 最近一次会话检查日志的读数，不代表每次查询时都重新读取了机器状态。

| 查询时间 | 账号状态 | API 分组 | 最近的会话检查日志 |
| --- | --- | --- | --- |
| 21:13:35 | `ready` | `ready` | 21:13:34，`status=assigned`、`vm_state=UNKNOWN` |
| 21:14:41 | `cooling_down` | `waiting` | 21:13:56，`status=assigned`、`vm_state=UNKNOWN` |
| 21:15:52 | `cooling_down` | `waiting` | 21:13:56，`status=assigned`、`vm_state=UNKNOWN` |
| 21:17:45（第四次） | `cooling_down` | `waiting` | 21:17:29，`status=assigned`、`vm_state=UNKNOWN` |

实际间隔分别为 66、71、113 秒，长于简报要求的约 30、30、60 秒；以表中实录为准。21:13:35 的 `ready` 出现在一轮尚未结束的检查期间：该轮 21:12:22 开始，21:13:56 以 `PRE_SUBMIT_TRANSIENT` 失败、`countsAsGeneric=false`；下一轮 21:15:57 开始，21:17:29 同类失败。短暂 `ready` 不能当作机器已 `RUNNING` 的证据。

第四次检查时，本地 API 返回既有 job `b33ecf11-05a3-4d3a-afdc-c59e0e9242ef` 的状态为 `queued`，更新时间仍为 15:13:40；在当日日志中没有找到该 job ID 的调度记录。API 状态与日志缺失分别如实报告，不推断日志未记录以外的行为。

## 定性

**其他：网页对话可正常回复，但未证明冷启动假设。** Profile 3 的已登录网页能回复指定消息；可观察范围内引擎的 absent 会话检查仍为 `UNKNOWN`，账号处于 `ready` 与 `cooling_down` 的循环，第四次为 `cooling_down`。没有观察到 `RUNNING` 或既有 job 被调度，且没有网页发送前后的机器状态证据可以证明机器从停止转为运行。网页和引擎是否对应同一个服务端身份也没有独立证实。

本次没有代登录、处理验证码、重启或停止引擎与桥、修改代码或提交新的引擎任务；网页只发送了简报指定的一句话。
