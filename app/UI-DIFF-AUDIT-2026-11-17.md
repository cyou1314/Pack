## A. 已确认差异

### 呈现 / 密度

- **D1 摘要卡展开态**：头部只有「房间摘要」四字——无调度员头像、无「钉在顶部」蓝签、右侧无「调度员维护 · 更新时间」；分组标签是纯文字，定稿为彩色签（已定=绿、进行中=蓝、待拍板=琥珀）；条目行距偏密。（折叠态一行「房间摘要 待拍板 N」✔ 对齐）
- **D2 额度过期呈现只做一半**（§11.4）：额度环过期转灰 ✔；但侧栏展开的额度文字块、成员详情的额度文字不转灰，也没有「已过期」旁注——数据已旧约 19 小时仍按实时样式显示。另（群主 2026-11-17 追加）：额度相关日期一律不带年份——侧栏重置日现为 `Text(Date, style: .date)` 全格式、成员详情「额度更新时间」为 `.formatted()` 默认格式，均带年份，并入 d-2 一并改。
- **D3 成员详情数字未格式化**：附加 token 显示原始数 `436000000`，侧栏同数据是 `436 M`。
- **D4 成员页头像不一致**：成员列表页 dispatcher 是参数化深色头像，聊天与侧栏里是紫猫头鹰设计图；同一成员两副面孔（absent/owner 待近看复核）。
- **D5 非对话页挂着对话家具**：成员 / 设置 / 收件箱页底部仍常驻聊天输入框，顶栏仍显示房间名，与定稿分页面形态不符。
- **D6 成员列表页过空**：一人一张高卡、只有名字 + 状态，密度与定稿（侧栏紧凑行 + 详情面板）不符。
- **D7 空房间形态**（§11.5）：实物是图标 + 标题 + 「派第一张活 / 查看成员」两按钮；定稿是裸标记 + 3 个快捷开始（查资料 / 生成图 / 巡检额度，点了只预填不发送）。另：空房间也挂着摘要条。
- **D8 房间顶栏无待批准标记**：定稿在房间名旁有琥珀待批准签，实物没有，待批准只能去收件箱看。**（已撤销：补验 P3 实证标记存在、仅无待批时不渲染，见 B2。）**
- **D9 切房间无加载态**：切进房间后消息未拉回前，先显示「还没有消息」空状态，数秒后消息才出现——空状态被当加载占位，会误导。
- **D10 @ 候选两处**（M12）：选中候选后插入的是纯文本 `@absent`，定稿为蓝色 chip；候选行带内部字样「Profile 3」灰字。
- **D11 离线成员缺「X 分钟前还在」**（§11.3）：成员行只有「离线」二字；dispatcher 无心跳，详情里只显「暂无」。
- **D12 成员详情缺项**：头部没有定稿的「本周已交活 N 单」；最近交活行缺用时（定稿有 done · 用时 · 产物）。

### 未实现 / 未接线

- **D14 系统通知 + Dock 角标未实现**（§12.2）：源码无 UserNotifications；收件箱三类齐了，但人不在电脑前没有任何提醒面。

- **D17 「更换头像」是禁用占位**：按钮标注「接口待接入」；中枢 avatar_combo 已支持，App 未接。
- **D18 交活产物无图 / 文件呈现**：信封产物只有文字引用，图片产物不渲染为图（与中枢无附件字段同根；附件通道是否立增量待群主定）。

### 已知偏差（B1-9 已交底、仍然存在）

- **D20 设置页三项**：凭证未迁钥匙串（界面如实标注）；成员巡逻间隔无中枢接口、以「本 App 状态刷新间隔」代（界面如实标注）；数据与备份位置只读。

- **D23 消息操作键离气泡太远**（群主 2026-11-17 亲点）：悬停操作组（复制/编辑/删除）排在整行末尾，AI 消息气泡靠左时复制键跑到行尾远处；应贴气泡相邻呈现（气泡与操作组同组贴合，不被整行宽度拉开）。源码定位：Views.swift `MessageOperations` 的 HStack 结构。

## B2. 补验结果（2026-11-17 下午，调度员在生产 App 逐项实证）

- **P1 分割线 ✔ 已实证**：临时房 p-verify-tmp 造三条消息、离房后再进——发丝线 + 「未读消息」标签出现在已读边界后第一条上方（双证：截图 + 无障碍文本）。文案与定稿「以下为新消息」略异，记微注、不单独成片。**但房间行未读数字徽标未实现**：源码确认 refresh 根本没解析 room_list 的 last_message_id，房间行无任何未读计数 → 新差异 **D21**（并入 B1-10d-4）。
- **P2 确认弹窗 ✔ 已实证**：标题「移除成员」+ 后果说明（在跑任务回池 / 消息与交活保留并标记已移除 / 头像组合释放 / 撤销访问）+ 取消 / 红色「确认移除」，对齐 §13.2；验后点取消、成员无恙。已移除成员的历史发言呈现仍无样本（此前移除的测试成员从未发言），保留未验并注明原因。
- **P3 批准卡待批形态 ✔ 完整实证**（造样本任务 #30 全程走完）：琥珀卡 = 「待批准 · 任务 #N」标题 + 任务名 + 说明 + 拒绝原因（可选）输入框 + 仅这一次（蓝）/ 总是允许（禁用）/ 拒绝；顶栏琥珀「待批准 1」胶囊与收件箱计数同步出现，点收件箱条目跳转并高亮该卡；拒绝后收拢为「已拒绝」行、任务自动 cancelled。**连带订正 D8：顶栏待批准标记其实存在，只是无待批时不渲染——审计当时无样本误判，D8 撤销。**「已过期 · 未决议」形态仍无样本（批准请求无过期样本），保留。
- **P4 任务板卡片 ✔ 结构对齐**：三段式（标题 / 一行摘要 / 发丝线 / 头像 + 名字 + 状态脚注）；[M4A] 角标在卡右上，与样机 ENG 角标同位。一处实差：**卡片标题缺「#编号」前缀**（样机为 #27/#25…）→ 新差异 **D22**（并入 B1-10d-4）。筛选四页签比样机多「owner 的」——B1-3 已交付口径，属演进不算差异。
- **P5 回执**：发送中… 有实现（源码 + 形态）；✓✓ 已送达 / 已认领多次实见。**失败态没有逐条回执**（源码确认）：发送失败时正文回填草稿 + 全局提示「操作未完成，请检查连接后重试」。定稿未明文要求逐条失败回执，记观察项、不立差异。
- 附带观察：①未钉住侧栏时切房间会自动收起为图标条（图钉钉住可常驻展开）；②D9 的空状态闪现在慢隧道下可持续 20 秒以上，更凸显加载态必要性；③临时房与样本任务已清理（p-verify-tmp 已归档、#30 已 cancelled），pack-main 只多了决议/系统行，无测试垃圾残留。
