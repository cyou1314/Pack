# ♾️（Pack）UI 设计定稿 · 待群主过目

版本：FINAL-DRAFT（2026-11-16 汇总，经群主逐项反馈收敛）
过目通过后：本文件升为仓库 `app/UI-DESIGN.md` 定稿，素材一并归档推仓。

---

## 1. 总原则

1. **克制、原生工具感**：向 Muse / Codex 的界面靠，不做「AI 味」设计——不用渐变紫、不用装饰色条、不用药丸堆砌、不用弹跳数字。
2. **白为主、黑为次、电光蓝 #1B7CF5 只点缀**：蓝只出现在主按钮、链接、激活态。
3. **灰色小字没必要就不出现**：界面文字只留功能必需的；层级靠字重和留白，不靠灰字堆。
4. **一个房间 = 一条连续对话**：房间即会话；调度员上下文按房间保持；群主在 ♾️ 里换新对话，Muse 才换新对话。
5. **动效只动状态变化那一下**：150–250ms 缓动，动完即静；装饰性动效（弹跳、脉冲、扫光）默认不开，只在聊天视图保留经群主点过头的少数几处（见 §8）。
6. **呈现纪律**（承规格附录 G.1）：长任务显示步骤时间线；批准请求带过期；额度数字诚实分级；交活必带信封摘要。

## 2. 全局视觉

- **色彩**：背景白 / 极浅灰 #F7F7F8；正文墨色 #141A22；次级灰 #5B6572；发丝线 #E3E8F0；蓝 #1B7CF5（深蓝字 #0D54B8）；状态色仅额度环与极少量状态字使用绿/黄/红。
- **应用标记**：~~软件内只用裸缎带星图形~~ **2026-11-16 群主改定：软件内左上角也用 App 图标原图**（圆角方形、带底、完整缎带星图），不用简化标记、不用裸图形；裸标记 `mark.png` 仅保留给空房间等少数场景，实现期以群主此版为准。
- **成员头像**：**入群即分配专属设计头像 + 名字**（学 GrokBot），不用字母圆头像。现行草案：absent = 橙色小狐狸，dispatcher = 戴耳麦的紫猫头鹰；中枢存图、下发 App。字母头像只是中枢占位，UI 期废止。
- **图标规范**：全套 Lucide 风格线性图标——24 网格、统一 1.8 描边、圆头圆角；不混用填充图标与表情符号。图标库 `icons.py`（inbox / chat / board / square-pen / file-plus / image / sparkles / layout / at-sign / settings / copy / pencil / trash 等）。

## 3. 聊天视图（主界面）

- **左栏两态**：
  - 收起态 = 64px 图标条：裸标记 → **新建对话键**（方框带笔，标记下方第一个）→ 收件箱（待批角标为琥珀点）→ 对话 → 任务板 →（底部）设置、额度环、群主头像。
  - 展开态 = 房间列表 + 成员列表；顶部整行「＋ 新对话」按钮；底部额度为用量卡（见 §4）。两态切换走宽度滑动 + 文字交叉淡入（动效 M13）。
- **消息流**：所有消息都是气泡——群主黑底白字靠右；AI 浅灰气泡靠左、带真头像与名字。无右栏 inspector 常驻。
- **回执**：自己消息下方小字三态：发送中… → ✓✓ 已送达 / 已认领（蓝）。
- **任务卡**：内容贴合宽度的紧凑卡（不横贯整屏）：标题 + 状态签（执行中/已交活）+ 一行步骤摘要 + 底部细进度。
- **批准卡**：同为紧凑卡：标题（待批准 · 类别）+ 一行说明 + 三档按钮「仅这一次（蓝）/ 总是允许 / 拒绝（红字）」；批准后整卡收拢成一行「✓ 已批准 · 仅这一次」。批准也可走规则库自动决议与独立审查（中枢已上线），UI 只呈现结果。
- **输入区**：底部大输入框；左侧黑圆「＋」点开菜单（从按钮处缩放弹出，动效 M14）：添加文件… / 添加照片… / 选择技能 / 选择模板 / 派活给 absent；右侧显示当前指派与蓝色发送钮；输入框上方一行小签显示批准模式（如「需批准 · 关」）。

## 4. 额度组件（定稿 v3）

- **环心只报剩余**（如 38%），数字正中锚点居中。
- **弧线渐变**（浅 → 深）带一点光泽；**平头收尾，环上不带任何端点**（已逐像素验证环带外 0 越界）。
- **三档颜色**：已用 <70% 绿 / 70–90% 黄 / >90% 红。
- **收起态**只一个小环，不挂任何小字；**展开态**用量卡两行：周额度（已用 % · 重置时间）+ 附加 token（剩余 · 不过期）。
- 数据为真实口径示例：absent 周额度已用 62%、周三 00:00 重置；附加 token 剩 436M、不过期。
- **口径纠正（2026-11-16 群主指出）**：Muse 成员**没有 5 小时窗口**——那是 Codex 的额度口径，初版从 Codex 组件借形时误带入，已撤。成员额度只有两部分：**周额度 + 附加 token**，全 UI 不得再出现 5 小时窗口。

## 5. 任务板（克制版定稿）

- **白底无列框**：四列靠对齐与留白分开——待认领 / 进行中 / 待验收 / 已完成，与中枢任务状态机一一对应（阻塞不单列）。
- **列头纯文字** + 灰色计数（不做药丸、不弹跳，数字直接变）。
- **卡片**：发丝线边框、8px 圆角、无阴影；标题 + 一行摘要 + 发丝线 + 底栏（小头像 + 名字 / 右侧时间或状态）。
- **标记**（[ENG] 等）是右上角一行小灰字，不是彩色签。
- **进行中**进度 = 卡片底部 2px 中性灰线，无扫光。
- **阻塞** = 淡红底不要、红条不要：只在底栏右侧一行红字「阻塞 · 等批准」。
- **待验收**卡带交活信封一行摘要；按钮「通过」黑底、「打回」纯文字。
- **已完成**卡标题转灰，右下角灰字「已关单」，不加绿勾圆圈。
- 顶栏筛选为文字页签（全部 / absent 的 / 我派的），激活项黑字 + 下划线。
- 点卡片跳回其所在房间的对应任务消息。
- **列高固定、列内滚动**（2026-11-16 群主定）：四列高度锁定在视口内，卡再多也只在列内滚动（滚轮），不许把界面越撑越长；列头与计数常驻可见，不随滚动消失。
- **横向一屏**（2026-11-16 群主定）：任务板整体严格收在窗口一个界面内，四列**等宽弹性**（窗口多窄列多窄、卡片文字随列宽换行），不许横向变长、不许横向滚动条；窄屏同理四列并排收进一屏。

## 6. 新对话与房间

- 入口两个状态都有（见 §3）：收起态图标条顶部方框笔键；展开态侧栏顶部整行按钮。
- 点后中枢 `room_create` 建房，新房间排列表最上，界面滑入新房间（动效 M16）。
- 房间行悬停右侧出「…」菜单（重命名 / 归档），与消息操作同一路子。

## 7. 消息操作

- 悬停消息时，**气泡右侧、与气泡垂直居中**淡入一行裸图标：复制 / 编辑 / 删除（无盒子、无边框，与 Muse 本人消息操作同路子）；按下删除变红。
- 删除 = 软删除：正文替换为「（已删除）」，记录与审计保留；编辑带「已编辑」标记；任务卡与决议消息不可删改（中枢 kind=decision 已上线）。
- **编辑的提交方式（2026-11-16 群主定，含当日修正）**：点编辑后气泡**就地变成输入框**（预填原文），**直接回车即保存，界面上不放任何按钮**；取消只留 Esc / 点开别处放弃，不显示出来；保存后正文更新并带「已编辑」标记。

## 8. 动效清单（定稿）

统一：150–250ms、ease-out；只动变化处。

**聊天视图**
- M1 消息入场：淡入 + 上浮 6px 落位
- M2 回执切换：发送中… → ✓✓ 已认领（变蓝）
- M3 流式回复：逐字显现；思考三点轮跳；思考秒数走字（Thinking… Ns）
- M4 成员状态点：呼吸环（执行中）
- M5 任务进度：细条前进 + 微光扫过（仅聊天视图任务卡）
- M6 任务完成：整条转绿、徽章变「已交活」
- M7 批准流程：批准条滑入 → 按钮按下 → 收拢成一行决议
- M8 收件箱角标：有新待批时轻弹一次
- M9 额度环：数值变化时弧线扫动 + 数字滚动
- M10 悬停操作：图标行从气泡右侧滑入淡入（见 §7）
- M11 ＋菜单：从按钮处 0.92→1 缩放 + 淡入，划过项高亮
- M12 @选人：候选在输入框上方弹出（带真头像），选中后变蓝色 chip
- M13 侧栏收起↔展开：宽度滑动、文字交叉淡入、额度条 morph 成环（反之亦然）
- M14 成员接活：成员行高亮一秒 + 状态点变蓝（脉冲一次）
- M15 发送失败：气泡轻抖两下 + 红叹号与「发送失败，点击重发」；重发转圈，成功变 ✓✓
- M16 切房间：旧房内容滑出淡化、新房滑入，房名与列表高亮跟随

**任务板**
- M17 卡片换列滑行：状态变化时整卡平滑滑到目标列落位，同列卡片依次让位（无弹跳、无弧线抬升）
- M18 新卡落入：顶部淡入 + 轻微下沉落位
- M19 计数变化：数字直接替换（无动效，或 120ms 交叉淡化）
- M20 批准落地：通过按钮按下态 → 卡片滑入已完成、标题转灰

**明确关闭**：计数角标弹跳、阻塞脉冲、任务板扫光/微光、彩色装饰线条与药丸。

## 11. 补充定稿（2026-11-16 下午，完整性补洞）

> 起因：定稿复盘发现六处只有主流程、没有完整形态。此节为增补，与前文同级生效；素材：`task-detail.png`、`deliverables.png`、`states.png`、`rooms-multi.png`（draw_gaps1.py / draw_gaps2.py）。

### 11.1 任务详情：就地展开
- 点任务卡在消息流里就地展开，**不另开页面、不恢复右栏 inspector**。
- 展开内容自上而下：标题+状态签 / 执行者·租约次数·尝试次数 / 步骤时间线（每步名称+耗时，进行中步带呼吸点）/ 交活信封全文（verdict、摘要、产物引用、自检）/ 转交记录与审计入口 / 「在任务板打开」。
- 展开动画：高度展开 200ms 缓动（新增 M21）；同一时刻只展开一张卡，展开另一张时前一张自动收起。

### 11.2 交活产物呈现
- 图片产物：直接在对话流出图，**卡片就是图本身，不带图下说明行**（「候选几、比例」这类信息正文里已经说了、形状也看得出来，不重复占空间，2026-11-16 群主定），点开看大图，**预览（灯箱）里也只有图本身，不带文件名等任何文字行**（2026-11-16 群主定）；**下载用图标表示，悬浮在图片内右下角：一枚简洁的细线向下箭头（Lucide arrow-down 式，无底钮、无托盘线、尺寸小、与图角等距对齐），不放图片外面、不用文字链接**（2026-11-16 群主两轮修正定版：圆钮版太大太丑，否决）。
- 文件产物：文件卡（类型签 + 文件名 + 大小），点开预览。
- 产物同时登记进任务详情的交活信封，事后可溯；禁止只丢一个裸链接交活。

### 11.3 异常状态
- **中枢断连**：内容区顶部一条浅琥珀色横幅「中枢连接已断开 · 正在重连」，输入框置灰占位「连接恢复后可发送」；只提示一次，不弹窗；重连后自动补齐消息，横幅淡出。
- **成员离线**：头像转灰、状态点转灰，成员行标注「离线 · X 分钟前还在」；其进行中任务卡标注「执行体离线 · 任务已回池」，不假装还在跑。
- **额度耗尽**：状态点转红，成员行红字标注重置时间；派给它的新任务照常受理，卡上标注「排队中 · 等额度恢复，或改派」。

### 11.4 额度新鲜度
- 额度数据超过 **15 分钟**未更新即视为过期：额度环与数字整体转灰，旁注「数据 X 分钟前 · 已过期」，点环触发刷新。
- 过期数字不得作为派活判断依据（呈现纪律：宁可灰着，也不用旧数字装实时）。

### 11.5 空房间与搜索
- 新房间空状态：居中裸标记 + 「新对话」+ 一句引导 + 3 个快捷开始（查资料 / 生成图 / 巡检额度），点了即预填输入框，不直接发送。
- 搜索：⌘K 打开命令面板式搜索，统一搜房间 / 任务 / 成员，分组呈现，方向键选择、回车打开、Esc 关闭；入口另在展开态侧栏顶部（图标条收起态不加搜索图标，保持干净）。

### 11.6 多成员形态
- 成员行信息密度不变：头像+状态点 / 名字 / 一行状态（执行中带任务号、耗尽带重置时间）。
- @ 候选与成员列表同序：可派的在前，离线/耗尽在后并标注状态——派活前就知道派不派得动。
- 任务板筛选行随成员数扩展为成员页签（全部 / 各成员），版式与既有文字页签一致。
- 新成员头像草案追加：scout = 灰狼（一只耳折）、ink = 黑猫（白耳尖），文件 `avatars/scout.webp`、`avatars/ink.webp`，与 absent/dispatcher 同一扁平系列，待群主认。

## 12. 补充定稿二（2026-11-16 下午，第二轮补洞）

> 素材：`member-detail.png`、`notify-settings.png`、`livecard-draft.png`（draw_gaps3.py）。与前文同级生效。

### 12.1 成员详情页
- **开关方式（2026-11-16 群主定）**：点头像/成员行打开，**再点一下同一成员即关闭**（toggle）；点另一成员直接切换内容；右上角叉只作备用，点面板外空白也可关闭——不许只能跑去右上角关。
- 入口：成员列表点头像、任务卡点头像、@ 候选长按，都进同一页（从右侧滑入的单页，不新开窗口）。
- 内容自上而下：头像+名字+状态（执行中带当前任务号、接入方式、心跳时间）/ 额度全貌（周额度环 + 附加 token，数据带时间戳、过期转灰，同 §11.4）/ 在跑的任务 / 最近交活（标题 + verdict + 用时 + 产物数）/ 已装技能（只读列表，发布与指派归调度员）。
- 本页不出现任何令牌、账号与登录信息。

### 12.2 通知与批准过期
- 待批准请求触发系统通知：标题「待批准」，正文写明谁、要做什么、还剩多久；点通知直达对应房间的那张批准卡。
- 菜单栏/Dock 图标带待批角标（数字，琥珀点风格与收件箱一致）。
- 批准过期不静默消失：卡片保留并标注「已过期 · 未决议，任务已按规则回池/改派」，群主回来能看到去向。
- 通知只报三类：待批准、交活待验收、成员掉线超过 10 分钟；普通消息不发系统通知。

### 12.3 活卡原地更新（防刷屏）
- 同一任务在聊天流里**永远只有一张卡**：进度、步骤、状态、徽章都在这张卡上原地更新，位置不变；交活后同一张卡变为交活态。
- 任务的历史轨迹不在聊天流堆消息，去任务详情（§11.1）与任务板看。

### 12.4 首次打开与设置页
- 首次打开三步：①连接中枢（地址自动发现，失败可手动填）②确认身份（本机为群主端，令牌入系统钥匙串）③进主房间。成员接入不在 App 内办（中枢侧调度员处理，红线不变）。
- 设置页只四组：中枢地址 / 批准默认模式 / 成员巡逻间隔 / 数据与备份位置。不堆开关；设置页不显示令牌原文（只显示「已存入钥匙串」）。

### 12.5 草稿按房间保留
- 每个房间的输入草稿独立保留：切走再回来，写了一半的话还在；房间列表对有草稿的房间在行尾标注「草稿」二字（琥珀色小字）。
- 草稿只存本机、发送后自动清除；不进中枢、不进房间历史。

### 12.6 添加成员入口（2026-11-16 群主追问后补，原定稿缺项）
- 入口：展开态侧栏成员列表底部一行「＋ 添加成员」。
- 面板流程：填名字 → 头像自动生成预览 → 「发起添加」后新成员以「接入中」状态进成员列表，接入完成后转正常状态。
- **接入方式不在面板里选（2026-11-16 群主定）**：ego / 桥（Muse4AI）/ 引擎都是过渡期实现手段，**成品里成员直接在 ♾️ 内登录自己的账号，Muse4AI 届时退场**；面板只写明这一句，不出现过渡工具的名字。
- **头像唯一性（2026-11-16 群主追问后定）**：不靠预做固定图池，头像**参数化生成**（动物种类 × 配色 × 配饰 × 底色，组合空间上千），中枢维护占用登记——生成/更换时避开已占用组合、撞了顺延下一个空缺组合，唯一性由登记保证，与图池大小无关。
- **成员可自换头像（2026-11-16 群主提议）**：添加时的预览可「换一个」；入群后成员也能在自己详情页更换——只能从未占用组合里选，换后旧组合释放回池、新头像经中枢同步到所有端。群主/调度员可代为重置。
- 红线不变：登录由成员本人完成，密码/验证码不经过群主、聊天与 App；面板内明示这一句。App 只做发起与登记，不做账号登录本身。
- **成员登录流程（2026-11-16 群主追问后补）**：添加后成员状态「接入中 · 等待登录」→ 点开进入 **App 内嵌的服务方登录页**（成员本人在内嵌页输入账号密码，密码只提交给服务方、App 不接触不保存）→ 登录成功后会话保存在**该成员独立的本地分区**（成员间隔离）、状态转在线；会话过期时从成员详情「重新登录」同路径重走。现行 ego / 桥 / 自研引擎三条执行体本质都是这个形态，成品把内嵌会话收进 App 本体。
