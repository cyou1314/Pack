# Pack App UI 设计简报（v2 · 取代毛坯版）

调研依据（2026-11-13 实查）：
- AelionBot（aelion.chat，同类桌面多 agent 工作台）：一窗三栏——左选 Bot/群、中对话、右常驻「工作电脑 + 日程」状态栏。
- OpenMausBot（开源 GrokBot 替代）：成员像通讯录联系人一样列在侧栏；危险动作以「批准卡」直接出现在聊天流里（permission broker）。
- DMOps / StaffDeck（企业级多 agent）：聊天是流畅层，结构化层是看板 + 批准队列 + 协作面板嵌在聊天旁；状态机分栏（竞标/待认领/进行中/评审/完成）。
- 通行设计原则：纯聊天撑不起「动作」——批准必须给全上下文的大卡片而不是小按钮；空状态要给「可点的起始动作」而不是空白。

## 总布局：照 DSH 的骨架（一模一样即可，群主 2026-11-13 定）

参考对象就是本机 DeepSeek Harness 桌面端（已实机截图核对）：左浅灰蓝侧栏 + 右白色主区，单栏对话流，无右栏。Pack 直接套这副骨架，只换内容：

- 左侧栏（约 270pt，浅灰蓝底、全高）：
  - 顶部：Pack 图标 + 「Pack」字标，右上角收起侧边栏按钮。
  - 一个整宽大圆角按钮「＋ 派活」（对应 DSH 的「新会话」位置与样式，白底卡片式）。
  - 导航行（图标 + 文字，行高宽松）：群聊、任务板、批准中心（右侧琥珀色数字徽标）、成员。
  - 分区标题「房间」（小号灰字，右侧放搜索等小图标）：房间行 pack-main 可展开，其下是成员行——成员头像 + 名字，右侧对齐相对时间或状态小字（对应 DSH 的会话行：标题 + 「2天」）；选中行浅色圆角高亮。
  - 侧栏底部固定：群主行（群主头像 + 名字）+ 右侧连接状态胶囊（已连接=绿点 / 断线=红点「重连中」）。
- 主区（白底）：
  - 标题行：房间名（加粗）+ 后跟弱化小字信息（成员 2 · 在线 1）；右侧放状态胶囊（如「待批准 1」琥珀胶囊，对应 DSH 的「4/5 rot」位置）。
  - 页签行（DSH 式文字页签，选中蓝色 + 下划线）：对话 / 任务板 / 批准中心 / 成员——四个视图全在主区切换，不再用三栏分栏，不设右栏。
  - 内容区：对话视图为自上而下的消息流（成员消息带头像 + 名字行，任务卡/批准卡/交活卡嵌在流里，见核心组件）；任务板、批准中心、成员各自整页呈现（沿用此前组件设计）。
  - 底部 Composer（DSH 式大圆角卡片，浅描边 + 极轻阴影）：占位文案「发消息或派活，@ 成员指派」；卡内底行：＋按钮、「需批准」开关胶囊、弹性空白、指派成员选择、蓝色圆形发送按钮。
  - Composer 下方一条居中极小字状态行（对应 DSH 的 tok/s 状态行）：「中枢在线 · absent 空闲 · 今日完成 2」这类实时摘要。
- 窗口基准 1280×820 与 DSH 同档；侧栏可收起。

## 视觉系统（设计感的来源，逐项落实）

- **配色（群主 2026-11-13 定，与 App 图标同一套语言）：白为主、黑为次、蓝点缀，简洁干净。** 底色与卡片以白色/近白为主（深色外观下为近黑），文字与主要元素用黑，蓝色只做点缀——主按钮、链接、进行中状态、选中态，取图标里的电光蓝（约 #1B7CF5）。忌大面积渐变与彩虹色；阴影极轻、描边极细，靠留白和排版出质感。App 图标为群主给定图（黑缎带星 + 蓝光），已裁好存 app/Assets/AppIcon-1024.png，make-bundle.sh 自动生成 icns 装入。
- 状态色（克制使用，只出现在小芯片/小点/进度条上）：待认领=灰、进行中=蓝（主题蓝）、待批准=琥珀、待验收=橙、完成=绿、卡住/拒绝=红。
- 群主气泡：黑底白字（不用渐变）；主按钮：蓝底白字；品牌标直接用 App 图标图。
- 成员身份色：每个成员一个固定色（absent=紫），该色贯穿其头像、气泡描边、任务卡归属标、看板卡片，看一眼颜色就知道是谁。
- 卡片：圆角 12、白/深底随系统外观、1pt 细描边 + 极轻阴影；卡内信息三层：标题（13 semibold）/ 正文（12，次级色）/ 元信息行（11，弱化色 + 芯片）。
- 芯片：圆角胶囊、状态色 12% 透明底 + 同色文字，11pt semibold。
- 间距节奏：8 的倍数；消息间距 14，卡片内边距 12–16，分区间距 20。
- 字体：系统字体；房间标题 15 semibold，正文 13，分区小标题 11 大写字距弱化色。
- 头像：34pt 圆形，成员色渐变底 + 名字首字/缩写白字；右下角状态点（在线绿/忙碌琥珀/离线灰）带白圈。
- 空状态：居中一句话 + 两个可点建议芯片（如「派第一张活」「看看使用说明」），不留空白页。

## 成员头像系统（学 GrokBot：进群即有脸）

- 每个成员注册进中枢的那一刻，中枢就按其名字自动生成一张「设计头像」：一组身份渐变色 + 字母标（monogram），由名字哈希确定、永不变更，存中枢、下发给所有客户端——谁打开 App 看到的都是同一张脸。
- 数据已就绪：`member_list` 返回每个成员的 `avatar{glyph, c1, c2}`（如 absent = 橙→琥珀 +「A」，dispatcher = 紫→靛蓝 +「D」）。App 的 Member 模型加这三个字段并按它渲染：圆形渐变底（c1→c2 对角渐变）+ 白色 semibold 字母。
- 成员的身份色就取其头像渐变色，贯穿气泡描边、任务卡归属、看板卡片（见视觉系统）。
- 新成员加入零操作：注册即生成，App 下次轮询就带脸出现。以后可升级为 AI 生成的真人像头像，槽位不变。

## 核心组件（聊天流里的富卡片是重点）

1. 消息气泡：成员消息左对齐（头像 + 名字行 + 气泡，气泡左上小圆角）；群主消息右对齐（渐变气泡、白字、无头像）。
2. 任务卡（嵌聊天流）：状态色左边条 + 标题 + 执行者头像行 + 状态芯片 + 租约进度条（进行中才有，细条 4pt）+ 底部动作（看详情）。状态变化原地更新样式（完成变绿、加「成果摘要」一行 + 「已关单」芯片）。
3. 批准卡（嵌聊天流 + 批准中心各一份）：琥珀色边框 + 警示图标 + 任务全文 + 请求者与动作说明（「对外发送邮件给客户王总，含报价附件」这类具体后果）+ 大按钮「批准执行」（主）/「拒绝」（描边红字）+ 拒绝原因输入。批准中心里同款卡纵向排列。
4. 交活卡：成果全文（等宽字体呈现原文）+「验收关单」（主）/「打回重做」（描边）两个动作，关单后整卡转绿边并收起动作。
5. 系统消息：居中弱化小胶囊（「absent 加入了房间」「任务 #3 已释放回池」）。
6. Composer：圆角 12 的输入区，左侧「＋派活」切换（开启时输入区上方出现指派/需批准小工具行），右侧发送主按钮；回车发送。
7. 任务板卡：四栏（待认领/进行中/待验收/已完成）卡片同任务卡的紧凑版：标题 + 归属色点 + 芯片行 + 成果摘要（完成栏）。
8. 右栏状态卡：在干活成员的任务卡（租约进度条 + 已用时）、待批准提醒（琥珀）、最近完成 3 条（绿勾 + 标题）。

## 实现约束（SwiftUI / 本机环境）

- 本机只有 CLT、无完整 Xcode：**禁用 @State**（宏插件缺失会构建失败）；状态一律 @StateObject + @Published，局部交互状态放进 AppState。
- 不改 HubClient / Models 的接口与数据流，只重写视图层（ContentView 及子视图可拆文件到 Sources/PackApp/Views/）。
- 保持 15 秒轮询与现有全部动作接线（派活/批准/拒绝/关单/打回/取消/发消息/点卡跳详情）功能不回退。
- 构建走 app/make-bundle.sh（swift build + 组装 Pack.app + ad-hoc 签名），用 open 启动；交付标准：窗口截图自检对照本简报逐项核对（气泡、任务卡、批准卡、右栏、成员身份色、空状态），不合格自己迭代到达标再回贴。
- 深色/浅色外观都要成立（颜色用系统语义色 + 透明度，不写死白底黑字）。
